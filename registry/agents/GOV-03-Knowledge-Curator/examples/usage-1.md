# Usage Example — Post-Incident Capitalization

## Contexte
Incident de sécurité P2 sur le projet "Horizon" — fuite de données via API non authentifiée. L'incident est résolu par CORE-05 et CORE-07. GOV-03 est activé pour capitaliser.

## Déroulement
1. GOV-03 collecte les données de l'incident auprès de CORE-05, CORE-07 et EXP-05.
2. Rédaction du post-mortem : chronologie, cause racine, impact, correction, actions préventives.
3. Extraction des leçons apprises : besoin de revue systématique des endpoints API avant release.
4. Création d'un article dans la base de connaissances : "Checklist Sécurisation Endpoints API".
5. Proposition d'évolution à GOV-01 : ajout d'un critère QG sur la revue des endpoints.
6. Partage de l'article de veille : "Top 10 des vulnérabilités API 2026".

## Résultats
- **Post-mortem:** Publié et archivé dans CORE-06
- **Leçon apprise:** Revue API obligatoire avant release
- **Article KB:** "Checklist Sécurisation Endpoints API" créé
- **Proposition GOV-01:** Nouveau critère QG "Revue endpoints API" soumis
- **Article veille:** Publié et taggé #sécurité #API
