# Bonnes pratiques AKORIS

1. **Toujours commencer par un ADR** avant toute décision technique structurante.
2. **Documenter le contexte projet** avant le premier sprint : BUSINESS_CONTEXT, TECHNICAL_CONTEXT, GLOSSARY.
3. **Auditer chaque sprint** — ne jamais sauter l'audit, même pour un sprint court.
4. **Valider humainement** la release — l'automatisation prépare, l'humain décide.
5. **Capitaliser immédiatement** après chaque sprint : une leçon apprise oubliée est une erreur qui sera répétée.
6. **Ne pas surcharger le Core** d'agents — les experts sont activés à la demande.
7. **Versionner le Registry** — un projet ancien doit pouvoir synchroniser sa gouvernance.
